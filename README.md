<h1 align="center">Yōkify</h1>

<p align="center">Self-hosted serverless: от Git хранилище до работещо приложение, на твоята собствена машина.</p>

---

Публикуването на приложение на собствен сървър отнема време и изисква познания за сървърните технологии. Yōkify го прави с няколко клика: свързваш Git хранилище или посочваш папка, а Yōkify разпознава езика, пише Dockerfile, изгражда image и стартира приложението в Podman или Docker. Без Kubernetes, без облачен доставчик, с пълен контрол върху кода, данните и инфраструктурата.

Yōkify е за програмисти, малки екипи, стартиращи компании и училища, които искат собствена среда за хостване без сложна инфраструктура.

## Възможности

- **Git интеграция.** Свързваш акаунт в GitHub, GitLab или Bitbucket през OAuth 2.0 и избираш хранилище и клон. При всеки push webhook пуска ново публикуване.
- **Публикуване от папка.** Без Git: `yokify deploy ./my-app` публикува папка от машината.
- **Yōkipack.** Разпознава езика и рамката на проекта и предлага image, команди за инсталиране, изграждане и стартиране и порт. От тях пише Dockerfile, който виждаш и можеш да промениш преди публикуване.
- **Podman или Docker.** Работи с rootless или rootful Podman, както и с Docker, локално или на отдалечена машина.
- **Маршрутизатор.** Всяка функция получава собствен адрес. Маршрутизаторът насочва заявките към правилния контейнер и брои заявките.
- **Автоматично спиране.** Функциите могат да спират, когато не се ползват, и да се стартират отново при следващата заявка.
- **Логове в реално време.** Логовете от изграждането и от заявките идват в браузъра през Server-Sent Events.
- **Променливи на средата и тайни.** Задаваш ги за всяка функция. Тайните са скрити в интерфейса.
- **История на публикуванията.** Всяко публикуване пази commit-а, автора, продължителността и резултата.
- **Достъп отвън.** Публикува функциите в интернет през Cloudflare Tunnels или ngrok.
- **MCP сървър.** AI асистенти могат да публикуват и управляват функции през Model Context Protocol.
- **Потребители, сигурност и мониторинг.** Няколко потребители на една инсталация, със следене на състоянието на функциите.

## Уеб интерфейсът

| Страница | Какво показва |
|---|---|
| Функции | Всички функции със статус, image, адрес, заявки за 24 часа и последно публикуване |
| Нова функция | Избор на Git хранилище или папка, име и порт, с предложенията на Yōkipack |
| Функция | Общ преглед, настройки за изграждане и Dockerfile, променливи на средата и логове |
| Публикувания | Историята на всички публикувания |
| Логове | Живи логове от изграждането и от заявките за избрана функция |
| Настройки | Контейнерен двигател, Git акаунти, настройки по подразбиране, потребители и обновления |

## Как работи

```
Git хранилище или папка
        │
        ▼
   Yōkipack ── разпознава езика, пише Dockerfile
        │
        ▼
 Podman / Docker ── изгражда image и стартира контейнера
        │
        ▼
 Маршрутизатор ── адрес за всяка функция, брои заявките
```

Yōkify е клиент-сървър система с четири модула:

| Модул | Отговаря за |
|---|---|
| Git интеграция | OAuth връзката с GitHub, GitLab и Bitbucket, webhooks при push |
| Изграждане и публикуване | Yōkipack, изграждането на image и стартирането на контейнера |
| Маршрутизатор | Адресите на функциите, насочването на заявките и автоматичното спиране |
| Уеб интерфейс | Управлението на всичко от браузъра |

Сървърът е на Go и пази състоянието си в SQLite. Уеб интерфейсът е на SvelteKit и е вграден в Go binary-то, така че Yōkify е един изпълним файл.

## Изисквания

| Инструмент | Версия |
|---|---|
| Podman или Docker | с работеща услуга |
| Go | 1.27 или по-нова (само за изграждане от изходния код) |
| Node.js | 22 или по-нова (само за изграждане от изходния код) |

Подготовка на контейнерния двигател:

- **Podman на macOS и Windows:** веднъж `podman machine init`, после `podman machine start`.
- **Podman на Linux:** `systemctl --user enable --now podman.socket` (rootless).
- **Отдалечен двигател:** задай `CONTAINER_HOST` (и `CONTAINER_SSHKEY` при SSH).

## Първи стъпки

Изгради интерфейса, после сървъра:

```bash
cd ui
npm install
npm run build
cd ..
go build -o yokify .
```

Стартирай Yōkify:

```bash
./yokify
```

Отвори <http://127.0.0.1:8080>, свържи Git акаунт в **Настройки** и създай първата си функция от **Нова функция**.

## Разработка

Пусни Go сървъра и Vite dev сървъра едновременно. Vite препраща всяка заявка към `/api` до Go сървъра на порт 8080.

```bash
go run .
```

```bash
cd ui && npm run dev
```

Интерфейсът тогава работи на <http://localhost:5173> с презареждане при промяна.

Полезни скриптове в `ui/`:

| Скрипт | Какво прави |
|---|---|
| `npm run check` | Проверява типовете в Svelte и TypeScript кода |
| `npm run lint` | Пуска Prettier и ESLint |
| `npm run format` | Форматира всичко с Prettier |
| `npm run build` | Изгражда интерфейса в `ui/build`, който Go binary-то вгражда |

Pre-commit hook (Husky и lint-staged) форматира и проверява файловете, които commit-ваш.

## API

Всичко, което прави уеб интерфейсът, е достъпно и през REST API под `/api`, с отговори в JSON. Пълната документация е на <http://127.0.0.1:8080/docs/index.html>, докато сървърът работи. След промяна на коментарите на API-то я генерирай наново със [swag](https://github.com/swaggo/swag):

```bash
swag init
```

## Използвани технологии

**Основни:** Go, Svelte, SvelteKit, TypeScript, Podman, Docker, SQLite, OCI

**Допълнителни:** Vite, GitHub API, GitLab API, Bitbucket API, OAuth 2.0, Webhooks, Server-Sent Events (SSE)

## Структура на проекта

| Път | Съдържа |
|---|---|
| `main.go` | Стартира сървъра и се свързва с контейнерния двигател |
| `server/` | HTTP маршрути, работа с JSON и обслужване на single-page приложението |
| `podman/` | Връзката с Podman и операциите с контейнери и images |
| `docs/` | Генерираните Swagger файлове |
| `ui/` | Уеб интерфейсът на SvelteKit (Svelte 5, Tailwind CSS 4, shadcn-svelte) |
| `ui/embed.go` | Вгражда `ui/build` в Go binary-то |
| `config.toml` | Правилата на [revive](https://github.com/mgechev/revive) за Go кода |
